# Teamboard · 팀 프로젝트 협업 보드

팀의 할 일을 보드별로 나누고 **담당자·마감일·진행 상태를 함께 관리하는 웹 앱**입니다. 로그인한 사용자가 참여 중인 보드만 열 수 있으며 업무 데이터는 Supabase에 저장합니다.

Todoist 다크 모드 화면을 참고해 차콜 배경과 붉은 강조색을 적용했습니다. 전체 보드 목록과 상태별 업무 목록을 오가며 프로젝트를 관리할 수 있습니다.

- **소스 코드:** [GitHub 저장소](https://github.com/kjo35861/team-project-board)
- **배포 관리:** [Vercel 프로젝트](https://vercel.com/noi8/team-project-board) — 실제 서비스는 프로젝트의 **Visit** 버튼으로 접속합니다. 이 링크는 배포 관리 페이지입니다.
- **로컬 실행:** 개발 서버를 켠 뒤 [http://127.0.0.1:5173](http://127.0.0.1:5173) 접속
- **최종 문서 정리:** 2026-11-06

## 1. 목표와 현재 상태

브라우저에만 저장하던 개인 업무 보드를 로그인한 팀원이 공유할 수 있는 협업 도구로 발전시키는 것이 목표입니다.

인증, 공유 보드, 구성원·초대, 업무 생성·조회·수정·삭제, 전체 보드 목록과 다크 테마를 구현했습니다. 실제 Supabase DB 구조를 적용하고 기본 저장 동작을 확인했으며 GitHub `main` 푸시와 Vercel 자동 배포를 연결했습니다.

**기능 구현과 전체 운영 검증은 구분합니다.** 자동 테스트와 기본 DB 점검은 통과했지만 두 계정 간 전체 공유 흐름과 모든 DB 권한 시나리오를 검증한 상태는 아닙니다.

## 2. 주요 기능

| 영역 | 구현 내용 |
| --- | --- |
| 계정 | 이메일·비밀번호 회원가입, 이메일 인증 안내·재전송, 로그인, 세션 복원, 로그아웃 |
| 워크스페이스 | 참여 중인 전체 보드 목록, 보드 바로 열기, 로딩·빈 목록·오류·새로고침 |
| 보드 | 만들기, 소유자의 이름 변경·삭제, 현재 선택 표시 |
| 구성원 | 구성원 조회, 소유자의 일반 구성원 제거, 일반 구성원의 나가기 |
| 초대 | 소유자의 링크 발급·복사·취소, 상태 목록, 로그인 후 수락 |
| 업무 | 제목·설명·담당자·마감일·상태 입력, 생성·조회·수정·삭제 |
| 진행 관리 | 할 일·진행 중·완료 상태 변경, 동그라미 버튼으로 완료·완료 취소 |
| 찾기 | 제목·설명 검색, 상태·담당자 필터, 마감일 빠른 순·늦은 순 정렬 |
| 날짜 보기 | 현재 보드의 오늘·지연된 미완료 업무 / 이후 마감인 미완료 업무 구분 |
| 화면 | 다크 테마, 모바일 메뉴, 빈 화면 안내, 다크 스크롤바, 검색 단축키 |
| 실패 처리 | 입력·기존 카드 보존, 중복 요청 방지, 오류·재시도, 보드 전환 후 이전 응답 폐기 |

### 권한과 데이터 규칙

- 보드마다 소유자 1명이 있습니다. 소유자만 보드 이름 변경·삭제, 초대·일반 구성원 관리를 할 수 있으며 보드를 나갈 수 없습니다.
- 구성원은 업무를 생성·조회·수정할 수 있습니다. **업무 삭제는 해당 작성자 또는 보드 소유자만** 가능합니다.
- 담당자는 같은 보드 구성원만 선택할 수 있습니다. 구성원 제거 시 담당자 지정이 해제됩니다.
- 초대는 **7일 유효·1회 수락**입니다. DB에는 원문 토큰 대신 해시를 저장합니다.
- 최종 접근 제한은 DB의 행 수준 보안(RLS), 컬럼 권한, 서버 함수(RPC)에서 처리합니다.
- 업무 제목은 1~120자, 설명은 최대 2,000자, 보드 이름은 1~60자입니다. 앞뒤 공백과 날짜를 검증합니다.
- 날짜 기준은 **Asia/Seoul**입니다. 마감일이 없는 업무는 정렬 방향과 관계없이 뒤에 표시합니다.

## 3. 사용 방법

### 시작하기

1. 회원가입 후 받은 이메일의 인증 링크를 엽니다.
2. 로그인하고 **공유 보드 만들기** 또는 **보드 만들기**에서 이름을 입력해 저장합니다.
3. 목록의 보드를 선택한 뒤 **작업 추가**로 업무를 등록합니다.

초대를 받은 경우에는 전달받은 링크를 열고 로그인 후 화면에서 수락합니다.

### 전체 보드 목록

상단의 **내 워크스페이스**를 누르면 참여 중인 모든 보드가 나옵니다. 카드의 **보드 열기**로 이동합니다. 브라우저 뒤로·앞으로 이동도 사용할 수 있습니다.

목록 주소는 `/#workspace`, 개별 보드는 `/#board/<보드 ID>`입니다. 주소를 알아도 구성원이 아니면 서버 데이터에 접근할 수 없습니다.

### 업무 관리

- 작업 추가에서 제목과 필요한 설명·담당자·마감일·상태를 입력합니다.
- 상태 선택으로 진행 상태를 바꾸거나 동그라미 버튼으로 완료 처리합니다. 완료를 취소하면 **할 일**로 돌아갑니다.
- 업무의 `···` 메뉴에서 수정·삭제합니다. 삭제는 권한이 있는 사용자에게만 표시되며 확인창을 거칩니다.
- 보드 미선택·로딩·저장 중에는 관련 버튼이 비활성화됩니다. 구성원 목록을 읽지 못하면 잘못된 담당자 변경을 막기 위해 추가·수정 폼을 열지 않습니다. 새로고침으로 재시도합니다.

### 검색·필터·오늘·다음

- 검색은 제목·설명을 대상으로 합니다. `Ctrl+K` 또는 macOS `⌘+K`로 검색창에 이동합니다.
- 같은 필터 안의 선택은 OR, 서로 다른 필터와 검색 조건은 AND로 적용됩니다. 초기화로 조건을 지웁니다.
- 마감일 정렬 버튼으로 빠른 순·늦은 순을 전환합니다.
- **오늘**은 현재 보드의 오늘 마감·지연된 미완료 업무, **다음**은 오늘 이후 마감인 미완료 업무입니다.
- 다른 구성원의 변경은 **업무 새로고침**으로 확인합니다. 실시간 자동 동기화는 제공하지 않습니다.

### 구성원과 초대

왼쪽 프로젝트의 **구성원 · 초대**를 엽니다. 소유자는 초대 링크를 생성·복사해 전달하거나 대기 중인 초대를 취소합니다. 일반 구성원은 패널에서 보드를 나갈 수 있습니다.

원문 초대 링크는 발급 화면에서만 확인할 수 있습니다. 패널을 닫거나 이동한 뒤 같은 원문 링크를 다시 조회할 수 없으므로 안전한 경로로 전달합니다.

### 사용자 판단과 AI 활용

사용자는 디자인 참고 화면과 오류 화면을 제공하고 전체 보드 목록 이동·스크롤 디자인·작업별 커밋·푸시 방식을 결정했습니다. AI는 코드 분석·구현·오류 진단·DB 적용·테스트 실행·문서 정리·배포 확인을 수행했습니다.

개발 의뢰자가 직접 화면을 확인한 피드백을 반영했습니다. 외부 팀원 대상 사용성 조사나 다중 계정 검증을 완료했다고 주장하지 않습니다.

| 구분 | 사용 기술 |

| 프런트엔드 | HTML, CSS, 바닐라 JavaScript(ES modules), Vite |

```text
              └─ task-board-app.js: 현재 보드 업무
                       ↓
              src/lib/*-repository.js
                       ↓
              Supabase Auth / Data API / RPC / RLS
```

| 파일·폴더 | 역할 |
| --- | --- |
| src/main.js | 인증 후 초기화, 보드 선택·워크스페이스·초대 연결 |
| src/task-board-app.js | 업무 표시·입력·검색·필터·정렬 |

| src/lib/ | 인증·저장소·UI 제어·입력 검증 및 테스트 |
| theme.css | 최종 다크 테마·반응형·워크스페이스·스크롤 스타일 |
| styles.css, app.css, auth.css, board-ui.css, board-list.css | 기본·기능별 스타일 |
| supabase/migrations/ | DB 변경 파일 20개 |
| supabase/tests/database/ | 테이블·제약·권한·RPC pgTAP SQL 파일 20개 |
| vercel.json | 빌드·출력 폴더·SPA 경로 처리 |

DB는 `profiles`, `boards`, `board_members`, `tasks`, `board_invites`로 구성합니다. 과거 브라우저 업무 자료는 자동 병합하지 않습니다. 로그인 세션과 초대 수락용 임시 탭 저장은 업무 데이터 저장과 구분됩니다.

## 6. 설치와 로컬 실행

### 준비

Node.js **24.x**, npm, Git, Supabase 프로젝트가 필요합니다. DB 자동 테스트를 로컬에서 실행하려면 별도로 Docker와 CLI 환경을 준비합니다.

```sh
git clone https://github.com/kjo35861/team-project-board.git
cd team-project-board
npm ci
```

### 환경 변수

저장소 루트에 `.env.local`을 만들고 해당 프로젝트 값을 입력합니다.

```dotenv
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_PUBLIC_KEY=your-publishable-or-anon-key
```

공개 키에는 `sb_publishable_...` 또는 레거시 `anon` 키만 사용합니다. `service_role`, `sb_secret_...`, DB 비밀번호는 브라우저용 `VITE_` 변수에 넣지 않습니다. 환경 변수 파일은 Git에서 제외됩니다.

설정이 없거나 잘못되면 안내 화면이 나옵니다. 환경 변수 변경 후에는 개발 서버를 재시작합니다.

### Supabase 준비

1. 이메일 인증 공급자를 활성화하고 인증 메일을 수신할 수 있도록 설정합니다.
2. **새 DB**에서는 `supabase/migrations/`를 파일명 오름차순으로 적용합니다. SQL Editor에서도 순서를 지킵니다.
3. 이미 적용한 DB에 같은 생성 SQL을 재실행하지 않습니다. 수동 적용한 원격 DB는 CLI migration history와 실제 스키마를 대조한 뒤 관리합니다.
4. Auth URL 설정에 운영 주소와 필요한 개발·미리보기 리디렉션 주소를 등록합니다. 로컬은 실제 쓰는 `http://127.0.0.1:5173` 또는 `http://localhost:5173`를 등록합니다.

**Vercel 배포만으로 DB 테이블이 생성되지는 않습니다.** 운영 DB 구조는 2026-11-05 SQL Editor를 통해 적용·기본 점검했습니다.

### 실행 명령

```sh
npm run dev
```

안내된 주소로 접속합니다. index.html을 file://로 직접 열지 않습니다.

| 명령 | 용도 |
| --- | --- |
| npm run dev | 개발 서버 |
| npm test | 자동 테스트 한 번 실행 |
| npm run test:watch | 변경을 감지하며 테스트 실행 |
| npm run build | dist/에 배포용 파일 생성 |
| npm run preview | 빌드 결과 로컬 확인 |

## 7. Vercel 배포와 운영

| 설정 | 값 |
| --- | --- |
| Framework | Vite |
| Node.js | package.json의 24.x |
| Install Command | npm ci |
| Build Command | npm run build |
| Output Directory | dist |
| 경로 처리 | 앱 경로 직접 접속·새로고침을 index.html로 연결 |

Vercel에 `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLIC_KEY`를 필요한 Production/Preview 범위로 등록합니다. 개발 PC의 .env.local은 자동 전달되지 않습니다. Vite 변수는 빌드 시 반영되므로 변경 뒤에는 재배포합니다.

작업 흐름은 **변경 → 테스트·빌드 → 커밋 → origin main 푸시 → Vercel 배포 확인**입니다. 현재 Vercel 빌드 명령에는 npm test가 포함되어 있지 않으므로 테스트 실행은 별도로 필요합니다.

| npm test | **19개 파일 / 107개 테스트 통과** |
| npm run build | **통과** |
| npm audit --omit=optional | 보고된 취약점 **0건**. 실행 시점과 해당 검사 범위 기준 |
| 실제 DB 기본 점검 | 인증 역할에서 보드 생성·조회, 업무 생성·상태 변경, 구성원 조회, 소유자 제약 통과. 시험 데이터 롤백 |
| 실제 화면 | 조회 오류 복구, 전체 목록→보드 이동, 작업 추가 입력창, 모바일 390px 목록·가로 넘침 없음 확인 |
| Vercel | 이전 기능 변경들의 자동 배포 완료 확인 |
| 전체 DB 자동 테스트 | SQL 파일은 있으나 **전체 pgTAP 실행 미확인** |
| 다중 계정·접근성 | 두 계정 공유 전체 흐름, 모든 키보드·스크린리더 시나리오는 **추가 검증 필요** |

Vitest에는 모형 서버와 jsdom 테스트가 포함됩니다. 통과 결과가 실제 운영 DB의 모든 권한·다중 계정 동작을 증명하지는 않습니다.

### 제출 전 3단계 확인

1. 배포 서비스에 로그인해 **내 워크스페이스 → 보드 열기**를 확인합니다.
2. 업무 추가·수정·완료·취소·검색·필터·새로고침을 확인합니다.
3. 두 번째 계정으로 초대를 수락하고 공유 업무와 권한 제한을 확인합니다.

3번은 권장 점검이며 이미 통과했다고 기록한 항목이 아닙니다.

## 9. 문제 해결

| 증상 | 확인 내용 |
| --- | --- |
| 인증 설정 안내 | URL·공개 키·변수 이름 확인 후 서버 재시작 또는 Vercel 재배포 |
| 로그인 후 보드 조회·생성 실패 | 테이블·RLS·RPC 적용 확인. PGRST205는 테이블이 스키마 캐시에 없는 경우 |
| 작업 추가 비활성화 | 보드 선택, 로딩·저장 상태, 구성원 목록 실패 여부 확인 후 새로고침 |
| 이름 미설정 구성원 표시 | 현재 표시 이름 편집 화면이 없어 발생할 수 있음. 멤버십 오류와 구분 |
| 초대 실패 | 만료·취소·수락 여부와 로그인 계정 확인 후 새 초대 요청 |
| 다른 사람의 변경이 안 보임 | 실시간 동기화가 없으므로 목록·업무 새로고침 |
| 인증 후 배포 앱으로 돌아오지 않음 | Supabase Auth의 Site URL·허용 리디렉션 주소 확인 |
| 저장 실패 | 연결·로그인·멤버십 확인. 입력·기존 업무가 유지되므로 확인 후 재시도 |

## 10. 추가 작업 우선순위

현재 코드와 검증 기록을 바탕으로 정한 제안입니다. **최종 제출 전에는 기능 확대보다 1~3번을 권장합니다.**

| 순서 | 작업 | 이유와 완료 기준 |
| --- | --- | --- |
| 1 · 제출 전 | 두 계정·비구성원 배포 통합 점검 | 핵심 협업 흐름 미검증. 초대·같은 업무 조회·변경 후 재조회, 타인 업무 삭제·비구성원 접근 거부 기록 |
| 2 · 제출 전 | 격리한 DB의 pgTAP 전체 실행·이력 정리 | DB 테스트 20개 파일과 수동 적용 이력 확인 후 깨끗한 테스트 DB에서 전체 통과 |
| 3 · 제출 전 | 모바일·키보드·오류 점검 및 제출 증빙 | 긴 제목·많은 업무·초대 오류·탭 이동·초점 복귀 확인, 실제 서비스 URL과 대표 화면 기록 |
| 4 · 다음 개선 | GitHub Actions 자동 검증 | 현재 수동 테스트. PR/푸시마다 Node 24에서 npm ci·npm test·npm run build 실행 |
| 5 · 다음 개선 | 표시 이름·비밀번호 재설정 | 담당자 구분과 계정 복구 개선. 자기 이름만 변경, 재설정 메일·복구 후 로그인 확인 |
| 6 · 유지보수 | CSS·과거 코드 정리 | 여러 스타일과 테마 덮어쓰기의 충돌 감소. 미사용 코드 정리 후 기능·반응형 회귀 확인 |
| 7 · 선택 확장 | 동시 수정 충돌 안내·실시간 갱신·알림 | 기본 공유·권한 검증 후 별도 범위와 테스트 기준으로 구현 |

DB 테스트는 **운영 DB와 분리된 환경**에서 실행합니다. 현재 supabase/config.toml이 없으므로 설정부터 준비해야 합니다. Docker가 준비된 별도 로컬 환경에서 아래 흐름을 참고할 수 있습니다. 이번 문서 작업에서 실행한 명령은 아닙니다.

```sh
npx supabase init
npx supabase start
npx supabase test db
```

기존 원격 DB에 생성 SQL을 재적용하거나 초기화하는 대신 실제 스키마와 migration history를 먼저 대조합니다.
