# 사용자 흐름 및 화면 상태 설계

> `roadmap.md` 3단계 산출물입니다. 제품 정책은 `mvp-scope.md`, 기술·데이터 흐름의 한계는 `tech-stack.md`를 따릅니다. 주요 전체 MVP 흐름은 여전히 설계 상태입니다. 첫 로컬 기능 구현으로 보드 생성·선택·이름 수정·삭제와 보드별 업무 CRUD·검색·필터·정렬을 `index.html`에 연결했습니다. 로그인·초대·보드 권한과 서버 공유 저장은 구현되지 않았습니다.

## 1. 설계 목표와 원칙

- 가입·로그인에서 보드 참여, 업무 관리까지 사용자가 다음 행동을 쉽게 찾을 수 있게 합니다.
- 데이터를 불러오거나 저장하는 중, 데이터가 없을 때, 오류가 났을 때, 성공했을 때를 각각 구분해 안내합니다.
- 보드에 접근할 수 있는지와 업무를 삭제할 수 있는지는 화면 표시뿐 아니라 서버/API에서도 확인해야 합니다. 로컬 프로토타입은 로그인이나 팀 권한을 제공하지 않으므로 공유 데이터처럼 표시하지 않습니다.
- 로딩 화면이나 초기 보드에 실제 업무처럼 보이는 샘플 카드를 넣지 않습니다. 새로 추가된 업무가 없는 상태를 빈 보드로 보여줍니다.
- 상태는 색상만으로 표현하지 않고 텍스트도 함께 제공하며, 키보드 포커스와 모바일 조작을 고려합니다.
- 첫 MVP에는 실시간 푸시 갱신이 없습니다. 다른 팀원의 변경은 화면을 다시 불러올 때 반영됩니다(`tech-stack.md`).

## 2. 화면 목록

| 화면 | 들어오는 경로 | 주요 동작 |
|---|---|---|
| 가입·로그인 | 앱 첫 진입, 세션 만료, 초대 링크에서 인증 필요 | 이메일·비밀번호로 가입 또는 로그인 |
| 이메일 확인 대기 | 이메일 인증 전 | 인증 메일 안내, 인증 완료 후 계속 진행 |
| 로컬 보드 목록·화면 | 앱 첫 진입 또는 보드 선택 | 로컬 보드 생성·선택·이름 변경·삭제, 업무 관리 |
| 보드 화면 | 보드 목록에서 선택, 초대 수락 완료 | 업무 확인·추가·수정·상태 변경, 검색·필터·정렬 |
| 팀원·보드 관리 | 보드 화면의 팀원/보드 관리 진입점 | 구성원 확인, 권한에 맞는 초대·관리 작업 |
| 초대 확인·수락 | 초대 링크 열기 | 링크 상태 확인, 로그인·이메일 인증 후 보드 참여 |
| 업무 상세·입력 | 업무 카드 메뉴 또는 추가 버튼 | 업무 내용 수정·삭제, 새 업무 작성 |

**현재 구현:** 보드 화면의 로컬 보드 관리, 업무 추가·수정·삭제, 상태 변경, 검색·필터·정렬, 빈 상태와 저장 오류 안내가 포함됩니다. 로그인·초대·팀원 관리 화면은 아직 구현되지 않았습니다.

## 3. 전체 사용자 흐름

```text
앱 진입 (현재 구현: 로컬 보드 화면)
├─ 보드 목록에서 로컬 보드 선택 또는 새 보드 만들기
│  └─ 보드별로 분리된 업무 화면
│     ├─ 업무 추가 → 입력·검증 → 브라우저 저장 → 갱신된 보드
│     ├─ 업무 카드 메뉴 → 수정 또는 삭제 확인
│     ├─ 카드 상태 선택 → 로컬 저장 → 해당 열로 이동
│     └─ 제목·설명 검색, 상태·담당자 필터, 마감일 정렬
└─ 이후 MVP 흐름 (미구현)
   ├─ 비로그인 → 로그인 또는 가입
   │  ├─ 이메일 확인이 필요함 → 확인 대기 → 인증 완료 → 보드 목록
   │  └─ 인증된 계정으로 로그인 → 보드 목록
   └─ 보드 선택 → 보드 화면 → 팀원·보드 관리
      ├─ 소유자: 초대 링크 발급·취소, 팀원 관리, 보드 관리
      └─ 팀원: 팀원 확인, 보드 나가기

초대 링크 (미구현)
└─ 링크 확인 → 필요 시 로그인·이메일 인증
   ├─ 유효한 링크 → 참여 확인 → 보드 참여 → 해당 보드 화면
   └─ 잘못된/만료/취소/이미 사용된 링크 → 원인 안내와 다음 행동
```

**현재 앱의 첫 사용 흐름:** 빈 로컬 보드에서 업무를 추가하거나 보드 목록에서 새 보드를 만들 수 있습니다. 보드·업무는 현재 브라우저에만 저장됩니다.

## 4. 주요 화면과 동작

### 4.1 가입 및 로그인

가입·로그인은 Supabase Auth 연결 후 구현합니다. 화면 상단에서 로그인/가입 모드를 구분하고, 이메일과 비밀번호에 라벨을 붙입니다. 제출 중 중복 제출을 막고, 인증 필요·인증 실패·네트워크 오류를 이해하기 쉬운 안내로 표시합니다. 현재 로컬 프로토타입에는 인증 기능이 없습니다.

### 4.2 이메일 확인 대기

가입한 이메일 주소와 메일 확인 방법을 안내하고, 인증 완료 뒤 이어 가던 보드 목록 또는 초대 흐름으로 돌아갑니다. 재전송을 구현할 경우 요청 중·성공·전송 제한 상태를 구분합니다. 현재 구현되지 않았습니다.

### 4.3 로컬 보드 목록 및 보드 관리

- 현재 구현에서는 이 브라우저의 로컬 보드 목록을 표시합니다.
- 보드 이름을 앞뒤 공백 제거 후 1~60자로 제한하고, 이름 중복은 허용합니다.
- 새 보드를 만들면 새 보드를 선택하고, 기존 업무와 섞이지 않도록 보드 ID로 데이터를 분리합니다.
- 보드 이름 변경과 삭제 전 확인을 지원합니다. 보드를 삭제하면 포함된 업무도 함께 삭제됩니다.
- 기본 보드는 유지되며 삭제할 수 없습니다. 마지막 로컬 보드를 삭제하는 상태가 생기면 기본 보드로 돌아갑니다.
- 모바일에서는 보드 선택 메뉴를 표시합니다.
- 실제 인증 사용자별 보드 목록·소유권·팀 공유는 제공하지 않습니다.

### 4.4 보드 화면

**로컬 프로토타입에서 동작하는 흐름**

- 보드의 세 열과 검색, 상태·담당자 필터, 필터 초기화, 마감일 빠른 순/늦은 순 정렬을 제공합니다.
- 제목·설명 검색과 선택한 상태·담당자 조건을 AND로 적용하고, 한 필터 내 여러 선택은 OR로 적용합니다. 담당자 미정도 선택할 수 있습니다.
- 열별 수와 전체 수가 현재 검색 결과에 따라 바뀌며, 검색 결과가 없을 때 조건 초기화 안내를 보여줍니다.
- 업무가 전혀 없는 상태에는 첫 업무 추가 안내를 표시합니다. 샘플 업무를 실제 업무인 것처럼 넣지 않습니다.
- 다른 열의 추가 버튼은 그 상태를 기본값으로 지정해 입력 창을 엽니다. 카드 메뉴에서 수정·삭제하고, 카드 상태 선택으로 세 상태 사이를 이동할 수 있습니다.
- 각 업무는 선택한 로컬 보드의 `boardId`로 묶여 보드 간 분리됩니다.
- 브라우저에 저장된 업무는 같은 브라우저에서 다시 열 때 읽습니다. 다른 브라우저나 팀원에게 동기화되지 않습니다.
- 마감일은 `Asia/Seoul` 날짜 기준입니다. 오늘보다 이전인 미완료 업무에 지연 텍스트를 표시하고 완료 업무는 지연으로 표시하지 않습니다.
- 저장에 실패하면 성공한 것처럼 목록을 바꾸지 않고 입력을 유지해 오류를 안내합니다.

**아직 구현되지 않은 MVP 흐름**

- 실제 보드 권한 확인·서버 데이터 불러오기·팀원 간 공유
- 로딩, 세션 만료, 서버 네트워크 실패, 권한 없음 상태
- 팀원 관리, 초대 링크 발급·취소·수락

### 4.5 팀원 및 공유 보드 관리

공유 보드에서 팀원 목록은 해당 보드 구성원에게만 보여야 합니다. 소유자만 초대 링크 발급·취소, 팀원 제거, 보드 이름 변경·삭제를 할 수 있습니다. 팀원 제거 또는 팀원 본인의 보드 나가기 때 담당 업무는 담당자 미정으로 바뀌며, 업무 내용은 유지합니다. 이 권한 관리와 팀원 데이터는 현재 구현되지 않았습니다. 로컬 보드 이름 변경·삭제는 인증된 소유자 기능을 뜻하지 않습니다.

### 4.6 초대 링크 발급과 수락

소유자는 7일 유효·1회 수락 조건의 초대 링크를 만들고 복사·취소할 수 있어야 합니다. 초대받은 사용자는 링크 상태를 확인하고 필요하면 로그인·이메일 인증 후 수락합니다. 링크 만료·취소·중복 사용 및 수락 중 오류는 각각 안내합니다. 링크 원문 저장·권한 확인·DB 트랜잭션은 서버 연결 후 구현하며, 현재 동작하지 않습니다.

### 4.7 업무 상세·추가·수정

**현재 보드 화면에 구현된 내용**

- `할 일 추가` 버튼과 각 열의 추가 버튼이 입력 창을 엽니다.
- 제목은 필수이며 앞뒤 공백을 제거한 뒤 1~120자, 설명은 선택 사항으로 최대 2,000자입니다.
- 담당자는 현재 예시 목록에서 지정하거나 미정으로 두고, 마감일은 날짜로 지정하거나 비워 둘 수 있습니다.
- 상태는 `할 일`, `진행 중`, `완료` 중 선택하고 저장합니다.
- 카드 메뉴의 수정 동작은 기존 값을 채운 입력 창을 엽니다. 검증 오류나 저장 실패 시 입력한 값을 유지합니다.
- 상태 변경 결과는 해당 상태 열에 반영되고 성공 안내를 표시합니다.

**추가로 연결해야 할 내용**

현재 `localStorage` 저장은 단일 브라우저 프로토타입입니다. 서버 검증, 실제 로그인 사용자·보드 팀원 목록, 서버 저장 충돌 처리, 공유 보드 데이터가 아직 없습니다.

### 4.8 업무 삭제 확인

삭제 메뉴를 선택하면 업무 제목을 표시한 확인 창을 거칩니다. 취소하면 데이터가 바뀌지 않고, 확인 후 성공하면 카드와 수가 갱신됩니다. 현재 로컬 프로토타입은 예시 권한 없이 삭제 메뉴를 표시하므로, 실제 소유자·작성자별 삭제 허용 규칙은 서버 연결 후 적용해야 합니다.

### 4.9 검색·필터·정렬

- 입력한 검색어는 제목과 설명에서 대소문자 구분 없이 찾습니다.
- 상태 필터와 담당자 필터는 다중 선택을 지원하고, 담당자 미정을 포함합니다.
- 한 필터 안의 값은 OR, 검색어와 서로 다른 필터는 AND 조건으로 적용합니다.
- 초기화 버튼은 검색어와 필터를 모두 해제합니다.
- 각 열의 카드 수와 전체 결과 수를 다시 계산하고, 결과가 없으면 빈 상태를 보여줍니다.
- 정렬은 마감일 빠른 순/늦은 순 전환입니다. 마감일이 없는 업무는 뒤에 두고, 같은 날짜끼리는 최근 등록 순입니다.

## 5. 공통 상태 및 오류 안내

| 상황 | 현재 상태 |
|---|---|
| 첫 진입·빈 보드 | 로컬 업무가 없으면 첫 업무 추가 안내를 표시 |
| 검색·필터 결과 없음 | 조건에 맞는 업무가 없다는 안내 표시 |
| 입력 검증 오류 | 제목·설명 오류를 폼에서 안내하고 입력을 유지 |
| 브라우저 저장 실패 | 저장 성공 처리 없이 입력을 유지하고 저장 실패 오류 표시 |
| 저장 데이터 일부 손상·읽기 실패 | 지속 안내를 표시하고 기존 데이터를 덮어쓰는 저장을 중지 |
| 서버 조회·저장 실패 | 서버 연동 전이므로 아직 구현되지 않음 |
| 세션 만료·권한 없음 | 로그인·권한 연동 전이므로 아직 구현되지 않음 |
| 초대 링크 오류 | 초대 구현 전이므로 아직 구현되지 않음 |

기술 정보·키·원시 DB 오류를 사용자에게 노출하지 않습니다. 성공 및 오류 결과는 접근 가능한 알림 영역으로 전달하고, 폼은 명시적 라벨과 키보드 포커스를 지원합니다.

## 6. MVP 화면에서 동작하지 않는 표현

현재 화면에서는 구현하지 않은 알림, 목록 보기, 내 할 일, 별도 설정, 워크스페이스 선택, 초대, 팀원 관리를 실제 기능처럼 노출하지 않습니다. 담당자 정보는 예시 목록이며 팀원 초대·공유를 뜻하지 않습니다. `로컬 저장` 표시와 안내 문구로 브라우저 안의 데이터임을 드러냅니다.

## 7. 다음 단계로 넘길 내용

화면 흐름 설계에 더해 현재 보드의 첫 기능을 로컬 JavaScript로 구현했습니다. 다음은 로드맵 4단계 데이터 모델·접근 권한 설계입니다. 그 단계도 문서만 수정하지 않고 로컬 데이터 모델과 구현 기준을 같이 다룹니다. 실제 DB/RLS 적용은 Supabase 실행 환경과 프로젝트가 준비되어야 하므로, 해당 범위가 미완료라면 그 사실을 분리해 기록합니다.
