# 2·3번 파트 기능 구현 — 소단계 실행 계획

> 목표는 문서상 완료가 아니라 `mvp-scope.md`의 권한·업무 규칙에 맞는 Supabase 공유 보드와 업무 기능을 코드·DB·테스트로 구현하는 것입니다. 각 작업은 작은 단위로 나눴으며 실제 소요 시간은 환경에 따라 달라질 수 있습니다. 코드 작성과 실제 DB·브라우저 검증은 구분합니다.

## 파트와 현재 상태

| 파트 | 범위 | 완료 기준 |
|---|---|---|
| 선행 기반 | 인증·세션, Supabase 로컬 검증 | 인증과 데이터 기능이 연결되고 기준선이 확인됨 |
| 2번 — 공유 보드·구성원·초대 | 스키마, 권한, 보드·구성원 관리, 7일·1회 초대 | 복수 계정 공유와 비구성원 차단을 실제 검증 |
| 3번 — 공유 업무·화면 상태 | 서버 CRUD, roster 담당자, 검색·필터·정렬, 상태 처리 | 보드 구성원이 같은 서버 업무를 조회하고 권한 규칙 준수 |
| 최종 인수 | 자동화, DB 권한, 두 계정 통합, UI 점검 | 실제 확인된 범위만 완료로 표시 |

- Vite 진입점은 `src/main.js`이고 `src/lib/`에 Supabase 설정 및 인증 코드가 있습니다.
- 보드와 업무 화면은 현재도 사용자별 `localStorage`를 사용합니다. 팀원 간 공유는 연결되지 않았습니다.
- 2.1~2.20의 스키마·제약·RLS/RPC 및 pgTAP 테스트 코드가 작성되어 있으나 DB 적용·pgTAP 실행은 확인되지 않았습니다.
- 2.17 초대 발급은 원문 토큰 일회 반환·SHA-256 저장·168시간 만료를, 2.18 목록/취소는 토큰 비노출을, 2.19 수락은 잠금 후 만료 확인과 멤버십/수락의 원자 처리를 코드로 작성했습니다.
- 2.20 `list_board_member_profiles(uuid)`는 해당 보드의 구성원에게 `user_id`, `display_name`, `role`만 반환하며 프로필 직접 SELECT를 차단하는 방향으로 작성했습니다.
- **2.21~2.23 데이터 계층 코드 작성:** 보드 목록·관리 RPC, 구성원·초대 RPC 저장소 함수를 추가하고 Vitest 코드도 작성했습니다.
- **2.24~2.29 UI 코드 작성:** 보드 목록 상태·관리, 구성원 roster, 초대 발급/취소·수락 및 보드 전환 UI 코드와 테스트 코드를 추가했습니다. 실제 실행은 확인되지 않았습니다.
- **3.1 입력 검증 코드 작성:** `src/lib/task-validation.js`가 제목·설명·상태·날짜 입력을 검증·정규화하고 `src/lib/task-validation.test.js`가 경계 사례를 검사하도록 작성했습니다. UI·저장소 연결 및 Vitest 실행은 확인되지 않았습니다.
- **3.2 업무 조회 저장소 코드 작성:** `src/lib/task-repository.js`에 인증 확인, 보드별 `tasks` 조회, 응답 필드/범위 검증 및 정렬을 추가하고 `src/lib/task-repository.test.js`에 테스트 코드를 작성했습니다. 테스트/DB 실행과 업무 UI 연결은 미완료입니다.
- **3.3 업무 생성 저장소 코드 작성:** `createTask(client, boardId, input)`은 입력 정규화, 인증 확인, 허용 입력 필드만 삽입, 인증 사용자 기반 작성자 지정, 응답 검증을 수행하도록 작성했습니다. 입력·권한·네트워크 오류 테스트 코드를 추가했습니다. Vitest 및 Supabase 실행은 미확인입니다.
- **현재 위치:** 3.3 코드 작성. 다음은 3.4 업무 수정·상태 변경 저장소입니다. 업무 화면과 데이터는 계속 `localStorage` 기반입니다.

## 진행 규칙과 선행 조건

1. 번호 순서로 진행하고 해당 범위의 테스트 코드도 함께 작성합니다.
2. `mvp-scope.md`를 권한 기준으로 삼습니다. 보드 소유자 1명, 팀원은 본인이 만든 업무만 삭제, 소유자만 초대·팀원 관리·보드 삭제, 초대 7일 유효·1회 수락, 담당자는 같은 보드 구성원만 허용합니다.
3. 실제 Supabase 검증에는 CLI와 Docker 또는 검증 가능한 Supabase 프로젝트가 필요합니다. 외부 프로젝트·대시보드 설정, 명령 실행, 브라우저 확인은 로컬 환경에서 진행해야 합니다. 비밀 키를 저장소나 채팅에 넣지 않습니다.
4. 브라우저에는 Supabase URL과 공개용 키만 사용합니다. `service_role` 등 비밀값을 포함하지 않습니다.
5. MVP는 실시간 푸시를 약속하지 않습니다. 보드 재조회 시 서버 최신 값을 반영합니다.
6. 기존 localStorage 자료를 공유 원본에 자동 병합하거나 가져오지 않습니다.

### 2번 파트 통과 관문

- 소유자·팀원·비구성원 권한 테스트를 실제 DB에서 실행합니다.
- 비구성원의 직접 Data API/RPC 접근 거부를 확인합니다.
- 초대 만료·취소·재사용·동시 수락을 실제 DB에서 검증합니다.
- 실행하지 않은 검증은 코드 작성 완료와 구분해 기록합니다.
